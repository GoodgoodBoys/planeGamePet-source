# 在线人数终身首次提醒

运营方决定：业务总连接硬上限取消，100、200、500 个同时在线客户端各提醒一次，发件和收件均为 `planepet_public@163.com`。既有反滥用、Nginx、系统资源及累计凭据保护不改。此功能只在服务端运行，不要求测试者更新 EXE。

## 口径与存储

统计经过认证并完成 WebSocket 握手的当前连接数；不是注册人数、累计启动次数或同时对战人数。一台机器的双端测试算两条连接。连接数跨过多个阈值时分别记录，即使随后立刻下降也不撤销。只有部署启用之后的观测可以触发，不推断上线前的历史峰值。

网关 `Recorder.observe()` 只操作至多三条内存记录，专用线程将首次时间、人数、固定邮件 ID 写入 `/var/lib/plane-pet/online-alerts.db`。独立 `plane-pet-online-alerts.service` 负责发信，SMTP 超时不阻塞游戏事件循环。数据库不记录玩家身份、IP 或游戏内容，也不依赖用户是否同意产品行为统计。

数据库损坏时不清空重建、不自动重复通知。磁盘长期不可用并伴随进程崩溃，尚未持久化的短暂峰值仍可能丢失；`/admin/status` 的 `online_alerts_persistence_error` / `online_alerts_pending_persistence` 可用于排查，不能将这套小型机制宣传为零故障消息系统。

## 发信语义

- `pending`：等待提交；确定未提交成功的失败会指数退避重试，最长每小时一次。
- `sending`：先落盘再发信。
- `sent`：邮件服务商接受提交，**不代表已经进入收件箱**。
- `uncertain`：提交中断、超时或进程重启导致结果不确定。停止自动重发，以免重复发送。
- `failed`：明确永久拒收，不自动重试。

SMTP 无法保证绝对的“必达且只到达一次”。本方案优先满足不重复轰炸：对于 `uncertain` 应核对邮箱的收件/垃圾邮件和运维记录，只有确认未送达并明确授权后才人工恢复待发送状态；不要直接清库或删除记录。

## 密钥配置与测试

163 邮箱开启 SMTP 后使用单独的授权码，不使用邮箱登录密码。授权码只通过加密传输写入 `/etc/plane-pet/plane-pet-smtp.password`，root 所有、0400 权限；systemd `LoadCredential` 将它只读提供给发件服务。源码、命令参数、日志、公开压缩包中不得出现授权码。

若授权码曾出现在聊天或截图中，应撤销并重新生成。未完成安全配置和真实测试前，不宣称发信已启用。

使用 `online_alerts.py test-mail --password-file <私有凭据文件>` 发一封明确标注“配置测试”的邮件，不访问或消耗终身阈值记录。不得在生产库伪造 100 人来测试邮件。

## 查看与停用

`python3 /opt/plane-pet/gateway/online_alerts.py status` 只读显示三个阈值的记录与提交结果，不创建缺失数据库。

仅停止 `plane-pet-online-alerts.service` 可暂停发信，网关仍记录新达到的阈值；恢复服务后继续处理待发记录。已发或不确定的记录不会重发。不要操作其他项目或全局 Nginx/防火墙。

## 备份与恢复

新版 `backup-plane-pet.py` 自动包含存在的 `online-alerts.db`，用 SQLite 在线备份 API。SMTP 授权码不放入普通数据备份，应独立保管或重新签发。发信进程锁文件无需备份。

清零匿名统计不得清理人数提醒库；恢复旧游戏/统计备份不得回滚现存人数提醒库。整机恢复时应恢复最新人数提醒库并将遗留 `sending` 作为 `uncertain` 核查。切勿从旧快照覆盖已经发出的终身记录。

## 部署验收

先检查线上连接并备份；只更新 PlanePet 网关及新增的独立发件模块/服务。检查前后 FingerKnight、原游戏服务、Nginx 的进程和配置不变。先通过本地和隔离暂存测试，再在空闲窗口仅重启 PlanePet 网关。

验收应包含 99/100、199/200、499/500、一次跨多个阈值、回落与重启去重、磁盘忙、SMTP 失败/模糊结果、501 连接本地传输、旧防滥用回归、实际 TLS 连接和一封配置测试邮件。不要对共享 ECS 发起 500 人压力测试。
